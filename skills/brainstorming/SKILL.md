# Lightweight Brainstorming

Use conversation to find the smallest sound design before implementation.

1. Inspect the relevant project context before making assumptions.
2. Decide whether any ambiguity materially affects behavior, scope, architecture, or UX.
3. If the request is clear, briefly state the intended approach and proceed.
4. If clarification is needed, ask one focused question at a time. Prefer concise choices when useful.
5. Compare alternatives only when there is a real trade-off, lead with a recommendation, and explain why.
6. Confirm the direction before implementation only when the unresolved choice would materially change the result.

Keep designs in the conversation. Do not require spec files, plan files, commits, TDD, worktrees, subagents, formal checklists, or ceremony unless the user asks for them.

If the user explicitly requests the full or strict Superpowers workflow, use `full-superpowers` instead.
